# Trading System (Тестовое задание)

Бэкенд торговой системы для сопоставления встречных заявок (матчинга) на покупку и продажу ценных бумаг/валют.
Реализован на Spring Boot 3, Java 17, PostgreSQL и Flyway.

## Технологический стек

- **Java 17**, **Spring Boot 3.x**
- **Spring Data JPA** (Hibernate) + **PostgreSQL 16**
- **Flyway** (миграции базы данных)
- **Lombok**, **JUnit 5**, **Mockito**, **H2** (для тестов)
- **Docker / Docker Compose** (для локального запуска БД)
## Как запустить

1. Поднять базу данных PostgreSQL:
```bash
docker compose up -d postgres
```

2. Запустить приложение (Flyway автоматически накатит схему и тестовые данные):
```bash
mvn spring-boot:run
```

Приложение будет доступно по адресу http://localhost:8080.

## Ключевые архитектурные решения

### 1. Движок исполнения заявок

Алгоритм матчинга (`MatchingEngine`) использует биржевой принцип «Цена — Время»:

- Покупатель ищет лучшего продавца (минимальная цена), продавец — лучшего покупателя (максимальная цена). При равенстве цен срабатывает время подачи.
- Исполнение по цене «стоящей» (resting) заявки. Агрессивная заявка (например, `BUY @ 105`) исполняется по цене контрагента, который уже стоял в стакане (например, `SELL @ 100`). Разница (`5 * кол-во`) остаётся на балансе покупателя как улучшение цены.
### 2. Система резервирования средств и бумаг

Чтобы исключить ситуацию, когда пользователь выставляет заявки на суммы/активы больше, чем у него есть, используется паттерн «Заморозки» (резервирования):

- В сущности `Account` есть `balance` и `reservedBalance`.
- В сущности `Holding` (портфель) есть `quantity` и `reservedQuantity`.
  При выставлении заявки средства/активы не списываются, а переводятся в резерв. При сделке или отмене резерв освобождается, а фактические балансы обновляются.

### 3. Управление схемой БД (Flyway)

В `application.yml` установлено `spring.jpa.hibernate.ddl-auto: validate`. Схема БД создаётся только скриптами Flyway (`src/main/resources/db/migration`). Это гарантирует, что изменения схемы контролируются, версионируются и не ломают приложение при рассинхроне сущностей и БД.


##  Основные REST API

| Метод | Путь | Описание |
|-------|------|----------|
| `POST` | `/api/instruments` | Создание инструмента (акции, облигации, валюта) |
| `POST` | `/api/accounts` | Создание торгового счёта |
| `POST` | `/api/accounts/{id}/holdings` | Зачисление активов на счёт |
| `POST` | `/api/orders` | Выставление заявки (мгновенно матчится, если есть встречная) |
| `PATCH` | `/api/orders/{id}` | Изменение цены/количества заявки |
| `DELETE` | `/api/orders/{id}` | Отмена заявки (освобождает резервы) |
| `GET` | `/api/quotes/{seccode}` | Текущие котировки (best bid/ask, last price) |
| `GET` | `/api/quotes/{seccode}/orderbook` | Стакан заявок (агрегированный) |
| `GET` | `/api/orders?accountId={id}` | Реестр заявок по счёту |
